Factory Inventory Management System

A demo full-stack application: a Vue 3 single-page app talking to a read-only FastAPI backend that serves in-memory data loaded from JSON files. There is no database.

System architecture

Two processes, one direct cross-origin connection. No proxy, no database, no authentication.

Tech stack

Versions are the declared ranges from package.json and pyproject.toml.

Frontend

Vue ^3.4 with the Composition API, Vue Router ^4.3, axios ^1.6. Built with Vite ^8. Node ^20.19 || >=22.12.

Backend

Python >=3.11, FastAPI >=0.110, uvicorn >=0.24, Pydantic >=2.5. Managed with uv.

Data

JSON files in server/data/, loaded once per process into module-level lists. Never mutated.

Testing

pytest, pytest-asyncio and FastAPI TestClient (httpx) under tests/backend/. There are no frontend tests.

Visuals

Custom SVG charts and CSS Grid. No chart library. Slate and gray palette, no emojis.

Tooling

Playwright and GitHub MCP servers via .mcp.json. Project subagents, commands and a skill in .claude/.

Data flow

What happens when a user selects Warehouse "Tokyo" and Period "2025-03".

  1. Filter change FilterBar updates shared refs in useFilters (selectedPeriod, selectedLocation, selectedCategory, selectedStatus). They are module-level singletons, so every view sees the same state.
  2. Watcher fires The active view's watch([...filters]) calls its load function, which reads getCurrentFilters(): {warehouse, category, status, month}. month is only present when the period is not "all".
  3. Request api.js drops every value equal to 'all' and calls, for example, GET http://localhost:8001/api/orders?warehouse=Tokyo&month=2025-03. The URL is hardcoded and the call is cross-origin.
  4. Filtering FastAPI runs apply_filters (warehouse exact match; category and status case-insensitive) and filter_by_month (quarter keys via QUARTER_MAP, otherwise substring match on order_date) over in-memory lists.
  5. Validation and response List endpoints serialize through a Pydantic response_model. Summary, spending and report endpoints return plain dicts.
  6. Store raw data The view saves results into refs such as allOrders, inventoryItems and summary, then clears its loading flag. Errors set an error message instead.
  7. Derive and render Computed properties (statusData, categoryData, orderTrendData, topProducts, revenueGoal and others) recompute, and the template re-renders KPI cards, SVG charts and tables. Currency conversion (150 JPY per USD) happens at display time only.

useFilters (shared filter state), useI18n (English and Japanese, locale stored in localStorage), useAuth (mock user and tasks).

Components

FilterBar, detail modals for product, inventory, backlog and cost, plus TasksModal, ProfileMenu, ProfileDetailsModal, LanguageSwitcher.

Conventions

Raw data in refs, derived data in computed properties. Use unique keys in v-for (SKU, month), never the index.

Known gaps

Things the code does not do, or does inconsistently. Worth knowing before building on it.

  • Missing endpoints api.js calls task and purchase-order routes (/tasks, /purchase-orders) that the backend does not implement. They return 404 at runtime.
  • Hardcoded URL The API base URL is hardcoded in api.js and in Reports.vue. There is no Vite proxy or environment variable.
  • Unrouted view views/Backlog.vue exists but is not in the router. Backlog is shown from the Dashboard instead.
  • Partial validation Only the list and by-id endpoints use response_model. Summary, spending and report endpoints return untyped dicts.
  • Hardcoded metrics The Dashboard's orders (187 of 200) and fill rate (96.8) are constants, not computed.
  • Test docs drift tests/TEST_SUMMARY.md describes an orders test suite that is not in the repo. The report endpoints are untested.
  • By design No database, no authentication, no write endpoints, wildcard CORS. Suitable for a demo only.

Run it

Both servers are needed. Browse the app at port 3000 and the API docs at port 8001.

# Backend  (http://localhost:8001/docs)
cd server
uv run python main.py

# Frontend (http://localhost:3000)
cd client
npm install && npm run dev

# Backend tests
cd tests
pytest
